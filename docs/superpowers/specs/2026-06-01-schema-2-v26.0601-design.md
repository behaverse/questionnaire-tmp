# Schema 2 v26.0601 Authoring Spec (OD-15 Pivot)

**Status:** Approved design captured in [design/05a_reusable_entities.md](../../../design/05a_reusable_entities.md); OD-15 resolved 2026-05-31. Ready for implementation.
**Scope:** Author Schema 2 (Questionnaire Definition) v26.0601 per OD-15. Archive v26.0528 under `versions/v26.0528/`. Schema 1 (Instrument) is unchanged and stays at v26.0528.
**Supersedes:** Schema 2 v26.0528 (commit `b910faa`, tag `v26.0528`). This is a **breaking** bump per CalVer severity policy — the entity model is structurally inverted.

This spec captures all design decisions resolved through the OD-15 grilling sessions (2026-05-29 / 2026-05-30 / 2026-05-31), with concrete JSON Schema fragments and implementation guidance.

## 3 — Top-level Questionnaire structure

The root Questionnaire JSON document. Renamed from the v26.0528 root structure to reflect the OD-15 model:

```jsonc
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://behaverse.org/schemas/questionnaire/v26.0601/schema.json",
  "title": "Questionnaire Definition",
  "type": "object",
  "required": ["metadata", "pages"],
  "properties": {
    "@context":    { "type": "string", "default": "https://behaverse.org/schemas/questionnaire/context.jsonld" },
    "metadata": {
      "allOf": [
        { "$ref": "https://behaverse.org/schemas/instrument/v26.0528/schema.json" },
        { "type": "object", "properties": { "id": { "pattern": "^qst_[a-z0-9_]+$" } } }
      ]
    },
    "style":       { "$ref": "#/$defs/Style" },
    "flow":        { "$ref": "#/$defs/FlowInstrument" },
    "pages":       { "type": "array", "items": { "$ref": "#/$defs/Page" }, "minItems": 1 },
    "blocks":      { "type": "array", "items": { "$ref": "#/$defs/Block" } },
    "subscales":   { "type": "array", "items": { "$ref": "#/$defs/Subscale" } },
    "logic":       { "type": "array", "items": { "$ref": "#/$defs/LogicRule" } },
    "scoring":     { "type": "array", "items": { "$ref": "#/$defs/ScoringDef" } },
    "validation":  { "type": "array", "items": { "$ref": "#/$defs/CrossQuestionValidationRule" } },
    "extensions":  { "type": "object" }
  },
  "patternProperties": { "^x_": {} },
  "additionalProperties": false,
  "$defs": { /* see §§4–9 */ }
}
```

**Differences from v26.0528 root:**
- `metadata.allOf` refs Schema 1 v26.0528 (unchanged).
- No top-level `translations` field (per OD-15: each entity carries its own `content` map).
- `pages[].elements[]` replaces v26.0528's `pages[].entries[]` — see §6.
- Other top-level fields (`style`, `flow`, `blocks`, `subscales`, `logic`, `scoring`, `validation`, `extensions`) are unchanged in name and meaning.

## 4 — `$defs` catalogue: content-bearing entities

Eight entities. Each has structural fields at the top level plus a `content` language-keyed map. The shared `ContentEntry<T>` pattern: each language key holds `{ status, ...translatable fields }`. We define one `$def` per entity rather than a parameterised content entry (JSON Schema 2020-12 has no clean parameterisation).

### 4.7 Option

The most complex content entity. Structural fields at the top; translatable fields inside `content.{lang}`. **Variant α** from OD-15 grilling: structural facts (input type, measurement type, per-choice value/index, min/max/step) stay outside `content`; translatable text (label, units, per-choice text) lives inside `content.{lang}`.

```jsonc
"Option": {
  "type": "object",
  "required": ["id", "input_data_type", "measurement_type", "content"],
  "allOf": [
    { "$ref": "#/$defs/OptionBase" },
    { "if": { "properties": { "input_data_type": { "const": "choice" } }, "required": ["input_data_type"] },
      "then": {
        "required": ["selection", "options"],
        "properties": {
          "selection": { "enum": ["single", "multiple"] },
          "options": {
            "type": "array",
            "items": { "$ref": "#/$defs/OptionChoiceStructural" },
            "minItems": 2
          }
        }
      }
    }
  ]
},
"OptionBase": {
  "type": "object",
  "properties": {
    "id":               { "$ref": "#/$defs/OptionId" },
    "dimension":        {
      "type": "string",
      "pattern": "^[a-z][a-z0-9_]+$",
      "maxLength": 64,
      "$comment": "Open vocabulary; preferred values: agreement, frequency, intensity, duration, count, presence, similarity, confidence, preference, quality, quantity, time, binary."
    },
    "input_data_type":  { "enum": ["choice", "number", "text"] },
    "measurement_type": { "enum": ["nominal", "ordinal", "interval", "ratio"] },
    "selection":        { "enum": ["single", "multiple"] },
    "min":              { "type": "number" },
    "max":              { "type": "number" },
    "step":             { "type": "number", "exclusiveMinimum": 0 },
    "min_selected":     { "type": "integer", "minimum": 0 },
    "max_selected":     { "type": "integer", "minimum": 1 },
    "placeholder":      { "oneOf": [{ "$ref": "#/$defs/PlaceholderRef" }, { "$ref": "#/$defs/PlaceholderInline" }] },
    "help":             { "oneOf": [{ "$ref": "#/$defs/HelpRef" },        { "$ref": "#/$defs/HelpInline" }] },
    "input_validation": { "oneOf": [{ "$ref": "#/$defs/RegExRef" },       { "type": "string", "minLength": 1 }] },
    "options":          { "type": "array", "items": { "$ref": "#/$defs/OptionChoiceStructural" } },
    "content":          { "$ref": "#/$defs/OptionContent" },
    "extensions":       { "type": "object" }
  },
  "patternProperties": { "^x_": {} },
  "additionalProperties": false
},
"OptionChoiceStructural": {
  "type": "object",
  "required": ["index", "value"],
  "properties": {
    "index": { "type": "integer", "minimum": 1 },
    "value": { "type": ["string", "number", "boolean", "null"] }
  },
  "additionalProperties": false
},
"OptionContent": {
  "type": "object",
  "patternProperties": {
    "^[a-z]{2,3}(-[A-Z][a-z]{3})?(-[A-Z]{2})?$": {
      "type": "object",
      "required": ["status"],
      "properties": {
        "status": { "$ref": "#/$defs/ContentStatus" },
        "label":  { "type": "string", "minLength": 1 },
        "units":  { "type": "string", "minLength": 1 },
        "options": {
          "type": "array",
          "items": { "$ref": "#/$defs/OptionChoiceContent" }
        }
      },
      "additionalProperties": false
    }
  },
  "additionalProperties": false,
  "minProperties": 1
},
"OptionChoiceContent": {
  "type": "object",
  "required": ["index", "text"],
  "properties": {
    "index": { "type": "integer", "minimum": 1 },
    "text":  { "type": "string", "minLength": 1 }
  },
  "additionalProperties": false
}
```

**Notes:**
- `content.{lang}.options` is only meaningful when the structural top-level `options[]` is present (i.e. for `input_data_type: choice`). The Library performs the cross-validation (every structural index has a matching content row); the schema doesn't enforce it because that cross-field rule would require JSON Schema 2020-12 `dependentSchemas` plus per-language array-shape coordination — possible but verbose. Defer to Library static analysis.
- The `placeholder`, `help`, `input_validation` `oneOf` between Ref and Inline supports both forms (per Q8a / Q9a resolutions).
- `PlaceholderInline` and `HelpInline` are the inline forms of Placeholder / Help (same shape as the saved entity but without `id`).

## 6 — Page composition: `elements[]` and per-element shapes

The biggest structural change from v26.0528. Page's `entries[]` is renamed to `elements[]`. Each element is one of four shapes — discriminated via `oneOf`.

### 6.1 Page

```jsonc
"Page": {
  "type": "object",
  "required": ["id", "elements"],
  "properties": {
    "id":          { "$ref": "#/$defs/PageId" },
    "title":       { "type": "string" },
    "description": { "type": "string" },
    "elements":    {
      "type": "array",
      "items": { "$ref": "#/$defs/PageElement" },
      "minItems": 1
    },
    "show_if":     { "$ref": "#/$defs/Expression" },
    "randomize":   { "type": "boolean", "default": false },
    "max_time_seconds": { "type": ["number", "null"], "minimum": 0 },
    "style":       { "$ref": "#/$defs/Style" },
    "translations":{ "$ref": "#/$defs/PageTranslations" },
    "extensions":  { "type": "object" }
  },
  "patternProperties": { "^x_": {} },
  "additionalProperties": false
},
"PageTranslations": {
  /* Page is a structural container with translatable title/description; same shape as MessageContent but for the Page's own translatable fields */
  "type": "object",
  "patternProperties": {
    "^[a-z]{2,3}(-[A-Z][a-z]{3})?(-[A-Z]{2})?$": {
      "type": "object",
      "required": ["status"],
      "properties": {
        "status":      { "$ref": "#/$defs/ContentStatus" },
        "title":       { "type": "string" },
        "description": { "type": "string" }
      },
      "additionalProperties": false
    }
  },
  "additionalProperties": false
}
```

**Note on Page's title/description:** these are translatable but Page is a structural entity, not a content-bearing one. I use a `translations` field here (different name from `content` on content-bearing entities) to signal that this is structural-translation rather than the entity's primary content. (Open: should this also be called `content`? See §16.)

### 6.2 PageElement (the four-branch `oneOf`)

```jsonc
"PageElement": {
  "oneOf": [
    { "$ref": "#/$defs/Section" },
    { "$ref": "#/$defs/MessageRef" },
    { "$ref": "#/$defs/PageElementSavedItem" },
    { "$ref": "#/$defs/PageElementInlineItem" }
  ]
},
"PageElementSavedItem": {
  "type": "object",
  "required": ["ref"],
  "properties": {
    "ref":      { "type": "string", "pattern": "^it_[a-z0-9_]+@v\\d{2}\\.\\d{4}(\\.dev\\d+)?$" },
    "id":       { "type": "string", "pattern": "^it_[a-z0-9_]+$", "$comment": "Optional override for response-data identifier — use when the same Item is referenced twice in one questionnaire (pre/post case)." },
    "required": { "type": "boolean" },
    "show_if":  { "$ref": "#/$defs/Expression" }
  },
  "additionalProperties": false
},
"PageElementInlineItem": {
  "type": "object",
  "required": ["question", "option"],
  "properties": {
    "id":       { "type": "string", "pattern": "^it_[a-z0-9_]+$" },
    "question": {
      "oneOf": [
        { "$ref": "#/$defs/QuestionRef" },
        { "$ref": "#/$defs/QuestionInline" }
      ]
    },
    "option":   {
      "oneOf": [
        { "$ref": "#/$defs/OptionRef" },
        { "$ref": "#/$defs/OptionInline" }
      ]
    },
    "required": { "type": "boolean" },
    "show_if":  { "$ref": "#/$defs/Expression" }
  },
  "additionalProperties": false
},
"OptionInline": {
  "$comment": "Same shape as saved Option but without the id field.",
  "type": "object",
  "required": ["input_data_type", "measurement_type", "content"],
  /* rest of fields same as Option, minus `id` */
}
```

**Discrimination:** the `oneOf` is unambiguous because:
- `Section` has `id` matching `^sec_`
- `MessageRef` has `ref` matching `^msg_…@v…`
- `PageElementSavedItem` has `ref` matching `^it_…@v…`
- `PageElementInlineItem` has `question` and `option` fields, no top-level `ref`

JSON Schema's `oneOf` handles this via "exactly one branch matches" semantics; each branch's `required` and `additionalProperties: false` rule the others out.

## 16 — Open implementation questions for the writing-plans phase

These are deliberately left for the writing-plans / implementation phase to resolve concretely.

1. **Page.translations naming.** Page (and Block, Section, Subscale) are structural entities with translatable `title` / `description`. They currently get a `translations` field; should they instead get a `content` field (uniform with content-bearing entities)? Recommendation: **rename to `content`** for uniformity, accepting that the distinction between "content-bearing" and "structural with translatable label" is mostly nominal. To confirm during plan-writing.

2. **`OptionInline` shape exactly.** The inline Option (on Page elements / Sections) is "saved Option minus the `id` field". Spec describes this prose-ly; the actual JSON Schema definition needs to be authored carefully (likely `allOf: [Option, { not: { required: ["id"] } }]` or a separate $def with most-of-the-same fields).

3. **Cross-validation: content.options index alignment.** When an Option has structural `options[]` with N rows, each language's `content.{lang}.options[]` should have N rows too with matching `index` values. This is a cross-field invariant the Library validates; the schema could enforce it via `dependentSchemas` + array `prefixItems`/`minItems` matching. Verdict: defer to Library. Plan should add a test for the Library-side validator.

4. **The `library_examples/` validator extension.** New code in `validate_schemas.py` to validate per-entity examples against specific `$defs`. The skeleton is in §11 of this spec; the plan should TDD it.

5. **Subscale's `weight_per_prompt` keying.** v26.0528 used `question_ids` and `weight_per_question`. v26.0601 uses `prompt_ids` and `weight_per_prompt`. The pattern key in `weight_per_prompt` should be `^pr_[a-z0-9_]+$` (matching `prompt_ids`).

6. **Migration importer (`13_importers.md` work).** Out of scope for this spec but flagged: the importer ingests legacy `survey_db.sqlite` and produces saved Library entities. Volume estimate: 793 Prompts, ~30 Options, 30 Contexts, 22 Instructions, 100 Messages, 11 Placeholders, 21 Helps, 7 RegExes, 935 Items (most inline within questionnaires), 35 Solutions. Migration spec is its own implementation push, not part of v26.0601 schema authoring.
